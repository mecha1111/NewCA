## 1. 절대 원칙 (모든 작업자 공통)

1. **EditMode 테스트 148/148 유지.** Runtime 로직(GameManager, EffectSystem 등 순수 C#)은 건드리지 않는 게 기본. 불가피하면 사유·영향 보고 후 멈춤.
2. **CardDatabase는 파일 I/O를 모른다.** 로드는 `CardDatabaseProvider`만.
3. **결과 인계 패턴 유지.** UI가 선택을 끝내고 결과만 GameManager에 넘긴다 (`ApplyBanPickResult` 방식). UI와 엔진이 같은 계산을 중복하지 않는다 (desync 방지).
4. **로직은 엔진이 진실.** UI는 엔진 상태를 그려주는 존재. UI에서 HP 계산 금지, 엔진 값 표시만.
5. **한 단계 끝나면 멈추고 검증 보고.** 헤드리스 실행 로그/렌더 캡처 포함.
6. **임의 추가 금지.** 시킨 것만. 명세에 없는 값은 "임의로 채움" 주석 + 보고.
7. 회전 요소는 **중심(0.5,0.5) 피벗**. CSS→Unity 회전 부호는 반대(`CssToUnitySign=-1`).
8. 카드 비율 **0.6545 (1000×1528)** 고정. 왜곡 금지.

## 2. 주석 규칙 (필수 — 전 파일 적용)

**목적: 다른 AI/사람이 처음 봐도 이해되게.**

```csharp
/// <summary>
/// [무엇] 밴픽 상태를 씬 넘어 유지하는 static 컨테이너.
/// [왜] BanScene↔PickScene을 오가며 진행되므로 씬 로드에 안 날아가는 저장소가 필요.
/// [주의] 게임 재시작 시 반드시 Reset() 호출 (static 잔존 버그 방지 — 실제로 겪은 버그).
/// </summary>
public static class BanPickState { ... }
```

- **모든 public 클래스/메서드에 `<summary>`**: [무엇]/[왜]/[주의] 3요소.
- **"왜"를 반드시 쓴다.** 특히 과거 버그에서 나온 코드(피벗 중심 회전, static Reset, 결과 인계)는 그 사연을 주석에 남긴다.
- 마법값 금지: 좌표·크기는 `const` + 출처 주석 (`// CARD_UI_FIX_SPEC.md 좌표표`).
- 복잡한 흐름(레디 캔슬, 액셀)은 메서드 위에 **순서도 주석**:
```csharp
// [흐름] 손패 클릭 → 사용가능 캐릭터 하이라이트 → 캐릭터 클릭
//        → (공격 && 리치내 2명 이상) 타겟 클릭 → 배치 확정
//        → 배치된 슬롯 X 클릭 시 캔슬(손패 복귀+코스트 환급)
```
- 한국어 주석. 파일 상단에 담당 모듈/의존 관계 헤더.

## 3. 화면 흐름 (프로토타입 확정본)

```
MainMenu → BanScene ⇄ PickScene (밴1→픽2→밴1→픽2)
        → PlaceScene   [신규] 출전 순서 배치
        → (상대 파티 공개 연출)
        → BattleScene  [초기코스트 → 턴루프]

턴루프: 드로우(2장) → 코스트배치(방금 뽑은 것만 0~2장)
       → 레디(스킬+캐릭터+타겟+신속, 전부 캔슬 가능)
       → 액션(신속그룹→일반그룹 속도순, 속도동점=액셀 연출)
       → 엔드(사망→전방 당김→코스트존) → 반복
```

Build Settings: MainMenu(0) → Ban(1) → Pick(2) → **Place(3, 신규)** → Battle(4). 기존 씬 인덱스 갱신 필수.

## 4. 시스템별 확정 명세

### 4-1. 밴픽 — 전체 공개 (기존 코드 수정)
- **비밀 없음.** 상대 밴/픽 즉시 공개.
- 밴 화면(상대 풀만): 내가 밴한 카드=BAN회색 / **상대가 픽한 카드="상대 픽" 라벨+클릭불가**
- 픽 화면(내 풀만): 상대가 밴한 내 카드="상대 밴" 라벨+회색 / 내가 픽=✓
- **상호 배제**: 상대 AI는 내가 밴한 카드를 픽하지 않는다. 나는 상대가 픽한 카드를 밴할 수 없다.
- 순서: 밴1→픽2→밴1→픽2 (GameRules 상수 참조 유지)

### 4-2. 배치 (PlaceScene — 신규)
- 픽한 4장을 **카드 클릭 → 슬롯 클릭**으로 P1~P4 배치
- **화면상 오른쪽 = P1 = 전방** (전투와 동일 방향, 혼동 방지)
- 캔슬: 채워진 슬롯 클릭 → 비워짐. 4장 다 배치해야 확정 활성
- 라벨은 슬롯 **바깥 위** ("P1 · 전방") — 카드와 겹침 금지
- 확정 → 상대 파티 공개 연출 → Battle

### 4-3. 코스트 — 레스트/언탭 (중요: UI 표현)
- 코스트 = 코스트 존 카드 **총량**(pool). 사용 시 **레스트**(꺾임 표시), 소멸 아님
- **매 턴 시작에 전부 언탭**(사용량 0으로)
- 초기: 손패 6장 중 2장 골라 코스트로 (Battle 진입 직후 단계)
- 매 턴 드로우 후: **방금 뽑은 2장 중에서만** 0~2장 코스트 선택. 기존 손패는 선택 불가(흐림+경고)
- 사망 캐릭터 → 코스트 존 (pool +1)
- 엔진의 `PlaceCostFromHand`/`PlaceCostFromDraw`와 연결. **엔진이 이미 레스트/언탭을 구현했는지 확인 후, UI는 엔진 상태를 pip(총량+꺾임)로 표시만** 할 것
- Phase 패널에 pip 표시: 금색=가용, 꺾임=레스트

### 4-4. 레디 — 선택+캔슬 (프로토타입 흐름 그대로)
```
손패 클릭 → 사용가능(무기매칭+코스트) 캐릭터 청록 하이라이트
  불가 사유는 로그로 명확히 ("코스트 부족(필요2)" / "(한손검) 쓸 캐릭터 없음")
캐릭터 클릭 → 공격스킬 && 리치내 적 2명 이상이면 타겟 지정 모드
  (리치내 적 하이라이트+거리표시 → 적 클릭 = 타겟 확정)
  리치내 1명=자동 / 0명=배치는 되나 불발 예고 / 회복=자동(최저HP 아군)
배치된 슬롯: hover 시 X버튼 → 캔슬(손패 복귀+코스트 환급+신속 환급)
```
- 엔진 `SubmitActiveCard(playerId, skill, user, asAccel, asSwift, skillOption)` 연결
- **타겟 지정**: 엔진의 TargetSelector 델리게이트에 UI 선택값을 넘기는 브릿지 필요 (5-3 담당)

### 4-5. 신속 (Swift)
- **자원**: 특정 캐릭터가 제공 (CharacterData에 swift 제공 수 — 데이터 확인 필요, 없으면 사용자에게 확인)
- 파티 확정 시 `swiftMax = Σ(파티 캐릭터 swift)`. **매 턴 리셋**(언탭)
- 배치된 스킬 슬롯 아래 ⚡버튼 → 토글. ON=자원 1 소모, OFF=환급. 자원 0이면 비활성
- 발동 순서: `[신속 그룹(속도순)] → [일반 그룹(속도순)]`
- 엔진 `asSwift` 플래그로 전달

### 4-6. 액셀 (Accel) — 자동 + 느린 연출
- 유저 지정 없음. **속도 동점(같은 신속 그룹 내, 다른 진영) 시 자동 진입**
- 연출 (전체 오버레이): 두 캐릭터 대치 → **A 덱탑 한 장 공개(0.7s 뜸)** → 일치 여부 표시(0.9s) → **B 공개** → 판정. 둘 다 일치 시 "재대결 N라운드" 반복
- 무기 일치한 쪽 선공, 진 쪽 **불발**. 로그에 각 장 기록
- 엔진의 액셀 처리와 결과 동기화 (엔진이 판정, UI는 연출) — **엔진 액셀 판정 로직 위치 확인 후 연출만 UI에서**

### 4-7. 엔드 — 사망 처리
- HP≤0 → 페이드아웃 → **전방(중앙 접점) 방향으로 당김 애니메이션** (내 카드는 오른쪽, 상대는 왼쪽) — R9 앞당김의 화면 표현
- 사망 캐릭터는 코스트 존으로 (pool+1)
- 전멸 판정 → 승/패 배너

### 4-8. 전투 화면 비주얼 (v2 확정)
- **점대칭(180도)**: 화면 중심(960,540) 기준. 상대 카드는 레이아웃 뒤집음(육각 아래+좌우반전, 이름 위, 스크림 위). 상대 덱 글자 180도
- 존: 상대덱 좌상(162°) ↔ 내덱 우하(-18°), 트래쉬/코스트 대각 반대
- **액트존 영역 박스** (4칸 감싸는 은은한 발광 테두리, 내=청록/상대=빨강)
- 세로: 상대액트(150고)~상대캐릭(229고)~중앙선(540)~내캐릭~내액트. 캐릭터 150×229, **액트 슬롯 150×150**
- 열: 내 [330,490,650,810] (우측끝 960=접점) / 상대 [960,1120,1280,1440]
- **중앙 접점에 장식 박스 넣지 말 것** (사용자가 제거 지시함)
- Phase 패널: 헤더(BATTLE+턴) + 페이즈 진행바(현재 발광) + 코스트/신속 pip + 로그(8줄) + 입체 버튼
- 사거리: 캐릭터 hover → 리치 내 적 노랑 발광+"거리 N" 칩, 밖은 어둡게
- 프리뷰: 좌측(26,420) 300×460, hover 시. **밴픽·배틀 전부**
- 손패: 부채꼴(±12°, lift 18, 피벗 0.5,0), hover 시 위로 확대

## 5. 업무 분할 (모듈 경계 + 담당 인터페이스)

> 각 모듈은 아래 인터페이스로만 서로 대화한다. 다른 모듈 내부 수정 금지.
> 의존 순서대로 진행: A → B → C → D (병렬 가능: B와 C 일부)

### 모듈 A — 밴픽 공개화 + PlaceScene (Opus 권장)
- 수정: `BanSceneController`, `PickSceneController`, `BanPickState`, `BanPickCardView`
- 신규: `PlaceScene.unity`, `PlaceSceneController`, `PlaceSlotView`
- 완료 조건: 밴픽 전체공개(라벨 포함) → 배치(캔슬 포함) → `BanPickState.PlacedOrder`(int[4], P1~P4의 카드 id) 확정 → 상대 공개 연출 → Battle 로드
- **출력 계약**: `BanPickState.PlacedOrder` — 모듈 C가 이것으로 파티 순서 바인딩

### 모듈 B — 카드 비주얼 정리 (Sonnet 권장)
- `CARD_UI_FIX_SPEC.md` 좌표로 `CharacterCardView` 재정비 (숫자 육각상단 y150, 이름 y955, 비율 0.6545, 색)
- 밴픽 카드(`BanPickCardView`)에도 동일 아트 구조 적용
- `CardHoverPreview` 컴포넌트 (밴픽·배틀 공용, 좌측 고정 패널)
- **출력 계약**: `CharacterCardView.Bind(unit)` / `CardHoverPreview.Show(cardData)` / `Hide()`

### 모듈 C — 전투 흐름 개편 (Opus 필수 — 엔진 브릿지)
- `BattleUIController` 개편: 초기코스트 단계 → 턴루프(드로우/newlyDrawn 코스트/레디/액션/엔드)
- 레디 상호작용: 선택→하이라이트→캐릭터→타겟→캔슬→신속토글 (4-4, 4-5)
- 엔진 브릿지: `PlaceCostFromHand/Draw`, `SubmitActiveCard(asSwift)`, TargetSelector에 UI 타겟 전달
- **먼저 엔진 확인 보고**: ①코스트 레스트/언탭이 엔진에 있는가 ②TargetSelector로 유저 타겟 지정 가능한가 ③신속 자원 데이터(캐릭터 제공)가 있는가 ④액셀 판정 훅 위치 — 4개 확인 후 설계 제시하고 승인받고 구현
- **출력 계약**: UI는 엔진 이벤트(OnPhaseChanged 등)+상태 조회로만 화면 갱신

### 모듈 D — 전투 비주얼/연출 (Sonnet 권장, C 이후)
- 점대칭 카드 뒤집기(상대), 액트존 박스, Phase 패널(진행바+pip+로그), 사거리 하이라이트, 사망 당김 애니메이션, 액셀 오버레이 연출(느리게), 부채꼴 개선
- 좌표는 4-8 표 그대로. 겹침은 배치 전 수학 검증 필수

### 모델 라우팅
- 명세 명확한 조립/뷰 = **Sonnet**
- 엔진 브릿지·통합·판단 = **Opus**
- Fable은 쓰지 않는다 (토큰 절약)
